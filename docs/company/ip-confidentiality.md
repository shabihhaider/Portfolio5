# IP Ownership & Confidentiality — Shabih.

---

## Intellectual Property Ownership

### Rule: Payment = Transfer of Ownership

All code, design, assets, and written content created specifically for a client project transfer to the client **upon receipt of full payment**.

Until full payment is received:
- The Developer retains all intellectual property rights to the work
- The client may not use, publish, or redistribute any deliverable
- The Developer may withhold delivery of source code and credentials until payment clears

### What Transfers to the Client (After Full Payment)

- All custom code written for the project
- All design files created for the project (if applicable)
- All content created specifically for the project
- Deployment configurations specific to the project

### What Does NOT Transfer to the Client

- **Proprietary tools and frameworks** the Developer built independently before or outside of this project (e.g., internal starter templates, utility libraries, boilerplate code)
- **Third-party libraries and open-source packages** — these are governed by their own licenses (MIT, Apache, etc.), which the Developer will use only within their allowed terms
- **API access or third-party service accounts** — the client must create and maintain their own accounts with services like OpenAI, Stripe, Vercel, etc.

The client receives a **perpetual, royalty-free license** to use the final delivered product. This is distinct from owning the underlying tools used to build it.

### Portfolio Rights

The Developer reserves the right to:
- Display the completed project in their portfolio on shabih.tech
- Reference the project type and general description in case studies
- Use screenshots or links to the live project

**Exception:** If the client requests confidentiality before project start, the Developer will not display the project publicly. This must be requested in writing before the SOW is signed.

## Confidentiality Policy

### What the Developer Keeps Confidential

The Developer will not disclose, share, or publish any of the following without explicit written permission from the client:

- Business processes and internal workflows
- Unreleased products, features, or business plans
- Client data, customer lists, or database contents
- Financial information or pricing strategies
- API keys, passwords, or credentials shared during the project
- Any information the client explicitly marks as confidential

### Duration

Confidentiality obligations remain in effect for **2 years after project completion**. After 2 years, information that has not become public on its own may still be treated as confidential at the Developer's discretion.

### Exceptions

Confidentiality does not apply to:
- Information that is or becomes publicly available through no fault of the Developer
- Information the Developer already knew before the project began
- Information received from a third party without a confidentiality obligation
- Information that must be disclosed by law or court order (Developer will notify client if legally possible)

### Handling Client Credentials

- Credentials shared during a project (hosting logins, API keys, CMS passwords) are stored securely and never shared with third parties
- Credentials are deleted from the Developer's records within 30 days of project completion unless the client requests otherwise
- Credentials are never transmitted in plaintext over unsecured channels (see communication-standards.md)

## NDA Requests

If a client requires a formal Non-Disclosure Agreement before sharing sensitive project details:
- The Developer will review and sign a standard NDA
- The NDA must be provided by the client or both parties can use this document as the basis
- NDA signing does not replace the Client Agreement — both are in effect
- Upwork's standard confidentiality terms apply automatically for all Upwork contracts

## Third-Party Services & Liability

For projects involving third-party services (OpenAI, Stripe, Twilio, etc.):
- The client is responsible for reading and complying with each service's Terms of Service
- The Developer is not liable for third-party service outages, price changes, or policy changes
- The Developer will flag any known compliance concerns (e.g., GDPR, data residency) but is not a legal advisor
- API keys for third-party services used in production must be in the **client's name and account**, not the Developer's
